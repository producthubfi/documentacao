O dado da HubFi já nasce com um código interno. O portal do banco mostra outro texto. O programa só precisa traduzir os dois para o mesmo código e preencher o step que está na tela.

  1. 1 Detectar o banco URL da aba → itau, caixa, inter, santander, bradesco
  2. 2 Ler o step visível título / stepper → dados pessoais, endereço…
  3. 3 Casar campos label do banco → chave HubFi, se confiança ≥ 0.90
  4. 4 Preencher só o visível nunca clicar Continuar. A pessoa avança.

Papéis — não misturar

  • applicant quem está no form do banco agora

Camada 2 · um arquivo por banco

Os 5 bancos não precisam de 5 dicionários

Cada banco é um adapter fino: hosts da URL, como o stepper se chama naquele portal, e atalhos só para o campo que o dicionário errar. CPF e e-mail quase sempre caem no genérico.

Contrato para o time

O que cada adapter implementa

interface BankAdapter {
  id: "itau" | "caixa" | "inter" | "santander" | "bradesco"
  name: string
  hosts: string[]                 // hostname termina com
  detectStep(doc: Document): {
    id: string                    // "applicant-data" | "address" | ...
    label: string                 // texto para o card da extensão
  } | null
  hints?: Partial<Record<FieldKey, string[]>>
  // CSS opcional. Confiança 1.00. Usar quando o label for ruim.
  write?(el: HTMLElement, value: string, key: FieldKey): boolean
  // máscara, React, select customizado
  afterWrite?(el: HTMLElement, key: FieldKey): void
  // esperar ViaCEP depois de cep
}

Matcher genérico (core)

  1. Normaliza o label: minúsculo, sem acento, sem “digite o”.
  2. Procura no dicionário. Match exato 0.98. Contém o alias 0.92.
  3. autocomplete="email" / cc-name vale 0.99.
  4. Hint do adapter vale 1.00 e ganha.
  5. Abaixo de 0.90: não preenche. Reporta “precisa de revisão”.
  6. Uma chave só casa com um input por step.

Filler (core)

  1. Só input/select/textarea visível e habilitado.
  2. Setter nativo + eventos input e change (React).
  3. Lê de volta. Se o valor não ficou, status “não permaneceu”.
  4. Não dispara clique em Continuar, Enviar, Próximo.

Não negociar

Regras de preenchimento

  • A extensão informa o banco sozinha, pela URL. A pessoa não escolhe “estou no Itaú”.
  • Se a aba não for um dos 5 hosts, o card de preenchimento some. O restante da operação continua.
  • Preenche só o step montado na tela. Campos de steps futuros não existem no DOM.
  • Titular da CNH ≠ proponente, se o CPF for outro. Não copiar Honorio no nome do Herminio.
  • Dado ausente (complemento) fica vazio e aparece como “sem informação”.
  • Dado divergente entre fontes da mesma pessoa: não preenche, pede revisão.
  • Nunca alterar CSS permanente do banco. Highlight no máximo durante o fill, e some.
